Boot the full AudioLens stack locally with Docker, load a sample dataset, and produce your first
saliency map against a Whisper checkpoint. About ten minutes, most of it model download.

<Badges items={["v1.0", "MIT", "FastAPI · React 18"]} />

<Callout title="Model weights download on first run">
  Only the worker container pulls weights, into `hf-cache`. The API image never imports the ML
  runtime.
</Callout>

## Prerequisites

<CardGrid>
  <Card kicker="REQUIRED" title="Docker">
    Docker Desktop on Windows or Mac, Docker Engine plus the Compose plugin on Linux.
  </Card>
  <Card kicker="WINDOWS" title="WSL 2 backend">
    Enable it in Docker Desktop settings for faster bind-mount I/O and GPU passthrough.
  </Card>
  <Card kicker="NVIDIA" title="Driver 555+">
    Verify with a base CUDA 12.6 image running `nvidia-smi` before booting the GPU profile.
  </Card>
  <Card kicker="APPLE" title="Native worker">
    Docker Desktop does not expose MPS, so run the worker outside the container to use the GPU.
  </Card>
</CardGrid>

## Install and boot

Pick the target that matches your accelerator. Every path ends with the same three services on the
same ports.

<CodeTabs labels={["docker", "nvidia", "amd rocm", "macos mps"]} label="Install target">

```bash
# 1. Clone
git clone https://github.com/ECHO-Lit/ECHO-LIT.git
cd ECHO-LIT

# 2. Copy env files (defaults work out of the box)
cp Backend/.env.example Backend/.env
cp Frontend/.env.example Frontend/.env

# 3. Boot the full stack
docker compose up --build
```

```bash
# Linux or WSL 2 with the NVIDIA Container Toolkit.
# Scale the all-queue local worker to 0 so only the GPU
# worker consumes GPU queues.
docker compose --profile gpu up --build \
  --scale worker-model-local=0 \
  redis api scheduler frontend worker-cpu worker-gpu
```

```bash
# Linux with a supported ROCm host driver.
docker compose --profile amd up --build \
  --scale worker-model-local=0 \
  redis api scheduler frontend worker-cpu worker-amd
```

```bash
# Docker Desktop cannot pass Metal into a Linux container.
# Keep the API in Compose, run the worker natively.
cd Backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

STORAGE_LOCAL_ROOT=shared-storage ML_DEVICE=mps \
  celery -A app.core.celery_app:celery_app worker \
  --queues=gpu-fast,gpu-large --concurrency=1
```

</CodeTabs>

## First analysis

<Steps>
  <Step title="Upload audio or pick a sample dataset">
    Drop your own files into the uploader, or start from the bundled Common Voice and RAVDESS
    subsets. Dataset paths inside the container are case-sensitive, for example
    `data/common_voice_valid_dev`.
  </Step>
  <Step title="Select a model">
    Choose a Whisper or Wav2Vec2 checkpoint. The first selection triggers a weight download into the
    worker cache; pre-warm it if you want an instant first run.
  </Step>
  <Step title="Read the prediction">
    The transcript panel aligns prediction against ground truth word by word and reports WER, CER
    and Levenshtein distance per datapoint.
  </Step>
  <Step title="Generate a saliency map">
    Run Grad-CAM or integrated gradients over the waveform. Segments are ranked by their
    contribution to each predicted token and highlighted on the shared timeline.
  </Step>
  <Step title="Perturb and compare">
    Add noise, shift pitch, clip or mask a region, then watch the metrics move. Robustness measured,
    not assumed.
  </Step>
</Steps>
